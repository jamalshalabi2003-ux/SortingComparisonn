## وصف المشروع

يهدف هذا المشروع إلى مقارنة أداء خمس خوارزميات للترتيب باستخدام لغة Java، وقياس زمن تنفيذ كل خوارزمية عند التعامل مع مصفوفة تحتوي على 100,000 عنصر، وذلك في أربع حالات مختلفة لترتيب البيانات.

الخوارزميات المستخدمة في المقارنة هي:

* Selection Sort
* Insertion Sort
* Bubble Sort
* Merge Sort
* Quick Sort

**حجم المصفوفة:** N = 100,000 عنصر

**وحدة قياس الزمن:** ميكروثانية (µs)

## تحليل نتائج الاختبارات

### 1. المصفوفة العشوائية (Random)

حققت Quick Sort أفضل أداء في هذه الحالة، بزمن تنفيذ بلغ 33,515 ميكروثانية، بينما سجلت Merge Sort زمنًا قدره 73,900 ميكروثانية.

أما Bubble Sort فقد سجلت أعلى زمن تنفيذ، حيث بلغ 21,726,410 ميكروثانية.

### 2. المصفوفة المرتبة عكسيًا (Reversed)

سجلت Merge Sort أقل زمن تنفيذ، بلغ 8,382 ميكروثانية، تليها Quick Sort بزمن 13,342 ميكروثانية.

في المقابل، سجلت Bubble Sort زمنًا قدره 9,998,005 ميكروثانية.

### 3. المصفوفة المرتبة جزئيًا (Partially Sorted 80%)

حققت Quick Sort أقل زمن تنفيذ في هذه الحالة، حيث بلغ 3,448 ميكروثانية، تليها Merge Sort بزمن 9,281 ميكروثانية.

بينما سجلت Insertion Sort زمنًا قدره 153,631 ميكروثانية.

### 4. المصفوفة المرتبة بالكامل (Sorted)

سجلت Bubble Sort أقل زمن تنفيذ في النتائج المسجلة، حيث بلغ 51 ميكروثانية، تليها Insertion Sort بزمن 491 ميكروثانية.

توضح هذه النتيجة أن بعض خوارزميات الترتيب البسيطة يمكن أن تحقق أداءً جيدًا عند التعامل مع بيانات مرتبة مسبقًا، إذا كان تنفيذها يسمح بالتوقف المبكر أو الاستفادة من ترتيب العناصر.

## مقارنة التعقيد الزمني والمكاني

| **الخوارزمية** | **أفضل حالة زمنية** | **متوسط الحالة** | **أسوأ حالة زمنية** | **التعقيد المكاني الإضافي**          |
| -------------- | ------------------- | ---------------- | ------------------- | ------------------------------------ |
| Selection Sort | O(N²)               | O(N²)            | O(N²)               | O(1)                                 |
| Insertion Sort | O(N)                | O(N²)            | O(N²)               | O(1)                                 |
| Bubble Sort    | O(N)*               | O(N²)            | O(N²)               | O(1)                                 |
| Merge Sort     | O(N log N)          | O(N log N)       | O(N log N)          | O(N)                                 |
| Quick Sort     | O(N log N)          | O(N log N)       | O(N²)               | O(log N) متوسطًا، وO(N) في أسوأ حالة |

* يتحقق أفضل تعقيد زمني لـ Bubble Sort إذا كان التنفيذ يتضمن آلية للتوقف عندما لا تحدث أي عمليات تبديل.

## الخلاصة

من خلال نتائج الاختبارات، يمكن ملاحظة وجود اختلاف واضح في أداء خوارزميات الترتيب حسب طبيعة البيانات.

حققت Quick Sort أفضل زمن تنفيذ مع البيانات العشوائية والمرتبة جزئيًا في هذا التشغيل، بينما حققت Merge Sort أفضل نتيجة مع البيانات المرتبة عكسيًا. أما Bubble Sort وInsertion Sort فقد حققتا أزمنة منخفضة جدًا مع البيانات المرتبة بالكامل.

توضح المقارنة أن Selection Sort وInsertion Sort وBubble Sort تمتلك تعقيدًا زمنيًا تربيعيًا في الحالة المتوسطة، بينما تتميز Merge Sort بتعقيد زمني O(N log N) في جميع الحالات. أما Quick Sort فتتميز بسرعة جيدة في المتوسط، مع إمكانية وصولها إلى O(N²) في أسوأ حالة.

بناءً على ذلك، تُعد Merge Sort وQuick Sort من الخيارات المناسبة عمومًا لترتيب المصفوفات الكبيرة، مع مراعاة طبيعة البيانات وطريقة تنفيذ الخوارزمية.

**ملاحظة:** تمثل الأرقام نتائج تشغيل البرنامج، وقد تختلف أزمنة التنفيذ عند إعادة الاختبار. كما أن مقارنة الأداء تعتمد على صحة تنفيذ الخوارزميات وتوحيد ظروف القياس.
